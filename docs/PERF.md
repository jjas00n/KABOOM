# 성능 측정 기록

## 2026-10-26 — 붕괴 후 FPS 저하 (Phase 3 → Phase 4 전)

증상: Medium 건물(Bodies 3743)을 많이 부수면 FPS 9~11. 목표 55fps 이상.

### 측정 방법

- 건물: seed 1, 6층, 4×3칸, Medium (부재 737 → 조각 3742 + 지면 = 바디 3743)
- 브라우저: headless Chrome + ANGLE D3D11 (실제 GPU, RX 6800). CPU는 그대로(x1) 또는
  DevTools CPU 스로틀 2배(x2). **x2가 사용자 증상(9~11fps)을 그대로 재현**해서 x2를 기준으로 본다.
- 디버그 GUI `Perf` 폴더 (0.5초 구간 프레임당 평균):
  Frame / Physics / Steps per frame / Update / Sync / Render(CPU 제출 시간) ms,
  Fixed / Dynamic / Awake / Sleeping 바디 수, Contact pairs(실제 접촉점이 있는 쌍)
- 시나리오
  - **Smash test**(디버그 GUI 버튼): 모든 층 정면+오른쪽 외벽 42곳을 한꺼번에 폭파 → 조각 1290개 동시 dynamic.
    최악 경우. 폭파 직후 0.5s / 1s / 3s / 10s 값을 읽는다.
  - **클릭 시나리오**: 건물 위 고정 지점 30곳을 0.5초 간격 클릭(15초) + 이후 5초. 실제 사용에 가까움.

### 결론과 남은 것

- 원인: 잔해가 잠들지 않음(더미 = 하나의 island) + spiral(최대 5스텝)로 증폭.
- 해결의 핵심: 느려진 조각을 **fixed로 굳혀 시뮬레이션에서 빼기** (`DebrisManager`).
  굳은 조각은 다시 맞으면 `FragmentSet.activate`로 깨어난다.
- 남은 한계: 1000개 이상이 **한 프레임에** 동시에 dynamic이 되는 최악 경우, 느린 CPU(x2)에서
  처음 2~3초는 14~20fps(물리는 그동안 실시간의 절반 속도 = 자연 슬로모션). 대포 한 발은 이보다 훨씬 작다.
- Phase 4 주의:
  - 지지 상실로 떨어지는 섬(island)은 compound 강체 1개로 떨어뜨려야 동시 dynamic 수가 안 폭증한다(ROADMAP 계획대로).
  - 굳힌 잔해 아래 조각이 나중에 빠지면 잔해가 공중에 뜰 수 있다 → CollapseSolver가 굳힌 잔해도 지지 검사 대상에 넣을 것.
- 렌더 CPU는 3~8ms로 여유. 붕괴 중 병목 아님.
