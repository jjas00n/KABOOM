# KABOOM — 진행 과정 & Claude Code 프롬프트

> 위치: `docs/ROADMAP.md` 에 두기. 각 Phase의 프롬프트를 Claude Code에 그대로 붙여넣으면 된다.
> 진행 체크는 아래 박스를 직접 체크하면서 관리.

## 사용법 (Claude Code 워크플로)
1. 레포 클론 → 루트에 `CLAUDE.md`, `docs/ROADMAP.md` 넣고 커밋.
2. 각 Phase 시작할 때 **Plan 모드**(Shift+Tab 두 번)로 프롬프트 입력 → 계획 확인 → 승인 후 구현.
3. Phase 끝나면 "검증" 항목을 직접 브라우저에서 확인 → 문제 있으면 그 자리에서 수정 요청.
4. Phase 단위로 브랜치/PR (`phase-2-fracture` 등). 막히면 `/clear` 후 "CLAUDE.md와 docs/ROADMAP.md 읽고 Phase N 이어서" 로 재개.
5. 컨텍스트가 길어지면 `/compact`.

## Phase 2 — 보로노이 분할 엔진 ★
**프롬프트**
```
Phase 2: 사전 분할(pre-fracture) 엔진을 만들어줘. 이게 이 프로젝트의 핵심이야.
- fracture/voronoi.ts: 입력 = 볼록 다면체(우선 박스) + 시드 점 배열. 각 시드마다 원본 다면체를 다른 시드들과의 수직이등분 평면으로 반공간 클리핑해서 볼록 셀을 만든다.
  - 가까운 시드만 검사하도록 공간 해시/kNN으로 가속
  - 결과 조각마다: 정점, 삼각형 인덱스, 법선, UV, 각 면이 "원래 외부면"인지 "절단 단면"인지 플래그(재질 그룹 분리용), 부피, 질량중심
- fracture/seeds.ts: 균일 랜덤, 지터 그리드, 특정 점 주변 밀집(적응형) 시드 생성
- 인접 정보: 두 셀이 같은 이등분 평면의 면을 공유하면 이웃으로 기록하고 공유 면적도 저장 (Phase 4 그래프용)
- fracture.worker.ts에서 돌리고 Transferable로 버퍼 전달
- vitest: 조각 부피 합 == 원본 부피(오차 1% 이내), 모든 조각이 볼록, 이웃 관계 대칭성
- 데모: 콘크리트 박스 1개(시드 300개)를 쪼개서 조각을 Rapier convexHull 바디로 만들고, 처음엔 fixed, 클릭하면 폭발 임펄스로 흩어지게
```
**검증**: 박스가 틈 없이 맞물려 보이다가 클릭하면 300조각으로 깨짐 / 단면 재질이 외면과 다르게 보임 / 테스트 통과

## Phase 3 — 절차적 건물 생성기 ★
**프롬프트**
```
Phase 3: 절차적 건물 생성기를 만들어줘.
- building/BuildingGenerator.ts: 파라미터(층수, 가로/세로 칸 수, 층고, 기둥 간격, 창문 비율, seed)로 사실적인 콘크리트 오피스 건물 생성
- 부재: 기초(지면 고정), 기둥, 보, 층 슬래브, 외벽 패널(창문 구멍 포함 → 창 주변을 여러 볼록 박스로 나눠 구성), 유리창, 옥상 난간
- 각 부재를 Phase 2 엔진으로 분할. 부재 종류별 시드 밀도를 config에서 조절 (외벽 패널 > 슬래브 > 기둥 순으로 잘게)
- 유리는 별도: 얇은 판을 잘게(크랙 느낌) 분할, 깨지면 가벼운 파편
- 부재 간 연결(기둥-슬래브, 패널-슬래브 등)도 인접 그래프에 포함
- 품질 프리셋 Low/Medium/High (총 조각 대략 1.5k/4k/8k), 생성 중 로딩 진행률 표시
- 렌더는 BatchedMesh, 재질은 외벽/단면/유리 3종
```
**검증**: 5~8층 건물이 멀쩡해 보임(틈/깜빡임 없음) / Medium에서 로딩 5초 이내 / 디버그 토글로 조각 경계 색칠 보기

## Phase 4 — 구조 무결성 & 연쇄 붕괴 ★
**프롬프트**
```
Phase 4: 건물이 '그럴듯하게' 무너지도록 구조 시스템을 만들어줘.
- building/StructureGraph.ts: 조각=노드, 인접=엣지(강도 = 공유면적 × 재질 계수). 기초 조각은 앵커
- destruction/Explosion.ts: 충돌 지점·운동에너지 기반으로 반경 내 엣지 파괴 + 조각들을 dynamic으로 전환하고 거리 감쇠 임펄스 적용
- destruction/CollapseSolver.ts: 엣지가 끊길 때마다 앵커에서 BFS → 도달 못 하는 덩어리(섬)를 찾아냄
  - 섬은 처음엔 하나의 compound 강체로 떨어뜨리고(성능+사실감), 지면/다른 조각과 큰 충격으로 부딪히면 내부 엣지를 끊어 개별 조각으로 분해
  - 하중 근사: 섬이 아니더라도 위층 질량에 비해 남은 지지 엣지 강도가 부족하면 점진적으로 끊김 (기둥 날아가면 그 위가 주저앉게)
- 동적 조각 끼리 큰 충격 시 추가 파괴(연쇄)
- DebrisManager: 동적 조각 상한, 오래 멈춘 조각 sleep, 작은 조각은 시간 지나면 페이드아웃
- 디버그: 그래프 엣지 시각화, 앵커 표시
- 테스트: 1층 기둥 전부 제거 시 상부 전체가 섬으로 판정되는지 vitest
```
**검증**: 옆면 맞추면 구멍만 뚫림 / 1층 모서리 기둥 쪽 맞추면 한쪽이 기울며 무너짐 / 붕괴 중 55fps 이상(Medium)

## Phase 5 — 대포 & 카메라 상태 머신
**프롬프트**
```
Phase 5: 마리오64 대포 '느낌'의 게임 흐름을 만들어줘 (에셋/디자인은 전부 오리지널).
- game/StateMachine.ts: IDLE → CANNON_CUTSCENE → AIMING → PROJECTILE_CAM → IMPACT → SPECTATE (CLAUDE.md 다이어그램대로)
- game/Cannon.ts: 건물에서 떨어진 언덕 위 대포(절차적 메시: 포신+받침), 지면에서 솟아오르는 등장 애니메이션
- camera/CutsceneCam.ts: 건물 전경 → 대포로 날아가는 스플라인 비행(약 3초, easeInOut), 클릭/Space로 스킵
- camera/AimCam.ts: 포신 시점, 마우스 yaw/pitch(각도 제한), 휠로 파워, 크로스헤어 + 예상 궤적 점선, 포신이 같이 회전
- game/Projectile.ts: 무겁고 빠른 포탄(CCD 켜기 - 터널링 방지), 발사 시 반동·연기
- camera/ChaseCam.ts: 포탄 뒤 체이스 캠, 스무딩
- 충돌 시: Explosion 호출 → IMPACT(timeScale 0.15로 0.3초 hit-stop + 카메라 흔들림) → SPECTATE로 전환
- camera/SpectateCam.ts: 처음 4초는 충돌 지점을 바라보며 천천히 도는 자동 연출, 이후 OrbitControls로 자유 관람
- 카메라 전환은 전부 부드러운 블렌딩(뚝 끊김 없이)
```
**검증**: 버튼 한 번으로 컷신→조준→발사→포탄 시점→충돌→건물 시점까지 끊김 없이 / 연속 발사 가능 / 포탄이 벽을 뚫고 지나가는 버그 없음

> 5+ 마법사(파이어볼) & 화재: Launcher 인터페이스로 대포/마법사 일반화, FireSystem(확산·연료·강도 감소 → 지연 붕괴). 완료.

## Phase 7 — 인크리멘탈 코어 ★
### 참고 게임 분석: Carpet Cleaning Simulator
- **핵심 루프**: 카펫을 문질러 거품을 만들고, 물로 헹궈 배수구로 밀어 넣으면 돈이 된다. 돈으로 장비를 사서 더 빨리, 더 많이 번다.
- **카펫 주문**: 런 중에 여러 카펫(작은 직사각형 / 원형 / 중간 크기 등) 중 골라서 청소한다. 모양과 크기에 따라 시간 대비 효율과 보상이 다르다.
- **완료 판정**: 청결도 90% 또는 100%에서 카펫이 '완료'되어 접히고 보상(Carpet Points)을 준다. "90%면 완료" 탤런트가 마지막 얼룩 찾기 노가다를 없애준다.
- **두 종류의 화폐와 리셋**: 런 안에서만 쓰는 돈 + 리셋 후에도 남는 포인트(탤런트 트리). 운석이 떨어지면 시간이 리셋되는 로그라이트 구조다.
- **희귀 보상**: '프리미엄 거품'은 낮은 확률로 15배 가치다.
- **유저 반응**: 문지르고 헹구는 손맛과 인크리멘탈 조합은 호평이다. 반면 거품이 많아지면 렉·크래시가 나는 점, 세이브 부재, 콘텐츠 부족은 혹평이다.

### KABOOM으로 옮기기
| Carpet Cleaning Simulator | KABOOM |
| --- | --- |
| 거품 → 배수구로 밀어 넣으면 돈 | 건물에서 떨어져 나간 파편 → 돈 (재질·질량별 가치) |
| 청결도 % | 파괴율 % (건물에서 떨어져 나간 질량 비율) |
| 90%에서 완료, 카펫이 접힘 | 파괴율이 임계값(기본 85%)에 도달하면 **완파 피날레**: 남은 건물이 한꺼번에 산산조각 + 완료 보너스 |
| 카펫 주문 고르기 | 철거 의뢰 게시판에서 건물 주문 고르기 (크기, 층수, 구조별 보상) |
| 프리미엄 거품 15배 | (Phase 10) 황금 파편 같은 희귀 파편 — 지금은 훅만 만들기 |
| 장비 업그레이드, 탤런트, 운석 리셋 | Phase 10으로 미룸 |
| 거품 많으면 렉/크래시 | 반면교사: 파편 수익은 물리 바디와 분리해서 계산하고, 피날레도 동적 바디 상한 안에서 |
| 세이브 없음 불만 | 처음부터 저장 지원 |

**설계 원칙**
- 돈 계산은 **물리와 독립된 순수 로직**(`src/economy/`)으로 만든다. 이벤트(조각 분리, 피날레, 주문 완료)만 구독하고, 숫자는 테스트로 검증한다.
- 지금은 돈을 **쓰는 곳이 없다**(업그레이드는 Phase 10). 대신 나중에 붙이기 쉽도록 모든 배율을 `Modifiers` 한 곳에서 계산하는 구조로 둔다.
- 건물을 여러 채 연속으로 불러오므로 **건물 교체 시 메모리 정리**(geometry/BatchedMesh/Rapier 바디/워커 버퍼 dispose)가 필수다.

### 7-1 경제: 파괴율 & 파편 수익
**프롬프트**
```
Phase 7-1: 인크리멘탈 요소의 기초로 '파편 = 돈' 경제를 만들어줘. docs/ROADMAP.md의 Phase 7 설계 원칙을 먼저 읽어.
1. src/economy/ 모듈 (물리/렌더와 독립된 순수 로직, 이벤트 구독만)
   - Wallet: 현재 돈, 누적 수익
   - FragmentValue: 조각 가치 = 질량 × 재질 단가(콘크리트 / 유리 / 기초 제외 등 config) × 주문 배율 × Modifiers. 너무 작은 조각도 최소 가치 보장
   - Modifiers: 모든 배율을 한 곳에서 합성 (지금은 주문 배율만 있음, Phase 10 업그레이드용 자리)
   - 희귀 파편 훅: 낮은 확률로 가치 N배인 조각 (기본 꺼짐, config로 켤 수 있게. 켜면 조각이 금빛으로 표시)
2. 수익 시점: 조각이 건물에서 '분리'되는 순간 (CollapseSolver/Explosion이 dynamic으로 전환하는 이벤트). 같은 조각에 두 번 지급하면 안 돼
   - 피날레(7-2)로 분리된 조각은 별도 이벤트로 구분
3. 파괴율: 기초를 제외한 전체 질량 중 분리된 질량 비율. CollapseSolver 갱신 주기에 맞춰 계산 (매 프레임 X)
4. 피드백 연출
   - 화면에 떠오르는 +$ 숫자: 조각마다 띄우지 말고 화면 공간 셀 단위로 0.2초 묶어서 합산 표시 (동시에 최대 N개, 풀링)
   - 큰 붕괴는 숫자가 커지며 강조, HUD 돈 카운터는 굴러가는 애니메이션
   - HUD: 현재 돈, 이번 건물 수익, 파괴율 바 (임계값 위치 표시)
5. config.ts에 ECONOMY 섹션 (재질 단가, 최소 가치, 희귀 확률·배율, 팝업 묶음 시간/최대 수)
6. vitest: 중복 지급 없음, 파괴율 0→100% 단조 증가, 질량 합 일치, 배율 합성 순서, 같은 seed·같은 입력이면 같은 수익(결정성)
7. PERF.md: 큰 붕괴 시 economy + 팝업 비용 측정 (목표: 프레임당 0.5ms 이하)
```
**검증**: 부순 만큼 돈이 오르고, 큰 붕괴에서 숫자가 시원하게 튐 / 같은 조각이 두 번 돈이 되지 않음 / FPS 영향 없음

### 7-2 완파 피날레: 거의 다 부수면 완전히 산산조각
**프롬프트**
```
Phase 7-2: 파괴율이 임계값(config, 기본 85%)에 도달하면 남은 건물이 완전히 산산조각나는 '완파 피날레'를 만들어줘.
카펫 청소 게임에서 90% 청결이면 완료되는 것처럼, 마지막 남은 조각을 찾아 쏘는 노가다를 없애고 시원한 마무리를 주는 게 목적이야.
1. 상태 머신: SPECTATE(또는 IMPACT) 중 임계값 도달 → FINALE → RESULT. 진행 중인 발사체와 카메라 전환은 깔끔하게 정리
2. 연출 (약 3~4초, 스킵 가능)
   - 임계값 도달 순간: 0.4초 hit-stop + '완파!' 연출, 건물이 진동하며 균열 확산 (Phase 6+ 손상 외관 효과로 damage를 1까지 빠르게 올림)
   - 붕괴: 남은 모든 엣지를 위에서 아래로 웨이브 형태로 끊어 (한 프레임에 몰지 말 것)
   - 산산조각: 남은 조각 중 일부만 실제 물리 dynamic으로 (상한 config, PERF.md 기준 동시 1000개 이하).
     나머지는 조각 위치·색으로 GPU 인스턴스 파편 파티클 폭발로 대체하고 원래 조각은 숨겨. 눈으로는 전부 터진 것처럼 보여야 해
   - 큰 먼지 구름 + 슬로모션 + 건물 주위를 도는 시네마틱 카메라
3. 보상: 남은 조각 가치 전부 + 완료 보너스(주문 보상) 지급. 숫자가 크게 터지는 연출
4. RESULT 화면: 이번 건물 수익(파편 / 피날레 / 완료 보너스 분리), 사용한 발사 수, 대포·마법사 비율, 소요 시간, 최대 연쇄 붕괴. '다음 주문' 버튼
5. 피날레 후 잔해는 DebrisManager로 굳히거나 페이드아웃해서 다음 건물 로딩 전에 정리
6. config.ts에 FINALE 섹션 (임계값, 웨이브 속도, 물리 조각 상한, 파티클 수, 슬로모션 배율)
7. 디버그 GUI: '파괴율 임계값까지 즉시 채우기' 버튼 (테스트용)
8. vitest: 임계값에서 정확히 1회만 발동, 피날레 중 추가 지급 없음(남은 조각 1회 정산), 결과 합계 = 지갑 증가분
9. PERF.md: Medium/High 건물 피날레 중 최저 FPS 측정 (목표 x1 45fps 이상)
```
**검증**: 85% 넘기는 순간 건물 전체가 시원하게 터지고 끊김이 적음 / 결과 화면 숫자가 지갑과 일치 / High 프리셋에서도 크래시 없음

### 7-3 주문 루프: 건물 여러 채를 주문해서 부수기 + 저장
**프롬프트**
```
Phase 7-3: 카펫 청소 게임에서 카펫 주문을 고르듯, 철거 의뢰를 골라 건물을 계속 부수며 돈을 버는 루프를 만들어줘.
1. 상태 머신 확장: ORDER_BOARD → LOADING → IDLE(대포/마법사 선택) → … → FINALE → RESULT → ORDER_BOARD
   CLAUDE.md의 게임 흐름 다이어그램도 갱신해
2. src/orders/ 
   - Order: id, 이름(가상의 의뢰인/건물명. 실존 회사·브랜드 금지), 건물 파라미터(층수, 칸 수, 창문 비율, 품질/조각 예산, seed), 기본 보상 배율, 완료 보너스, 예상 조각 수
   - OrderGenerator: seed 기반으로 매번 3장 생성. 크기 등급(소/중/대)별로 보상과 시간 효율이 다르게. 나중에 등급 해금(Phase 10)을 붙일 자리
   - 카펫 게임의 '직사각형 vs 원형'처럼 선택에 전략이 생기도록 특징 하나씩: 유리 많음(유리 단가 낮지만 잘 깨짐), 고층 슬림(무너지기 쉬움), 저층 넓음(조각 많음) 등
3. 주문 게시판 UI: 카드 3장 (건물 미리보기 썸네일은 오프스크린으로 작게 렌더 후 캐시, 층수, 크기, 보상, 특징 태그). 고르면 로딩 진행률 → 게임
4. 건물 교체 정리 (중요)
   - 이전 건물의 BatchedMesh/geometry/texture 참조, Rapier 바디·콜라이더, FireSystem 상태, 파티클, 워커 버퍼를 전부 해제
   - 테스트: 주문 10번 연속 진행 후 JS heap과 Rapier 바디 수가 첫 건물 수준으로 돌아오는지 (dev 전용 메모리 리포트)
5. 저장 (src/save/)
   - localStorage에 버전 있는 스키마로 저장: 지갑, 누적 통계(부순 건물 수, 총 파편, 최대 수익 건물), 현재 주문 게시판 seed, 설정
   - 저장/로드는 try/catch로 감싸고, 실패하거나 비어 있으면 새 게임으로 정상 시작. 스키마 버전이 다르면 마이그레이션 함수
   - 저장 시점: 주문 완료, 설정 변경, 탭 숨김(visibilitychange)
   - 디버그 GUI: 저장 초기화 버튼
6. 진행 중 포기: '의뢰 포기' 버튼 (그때까지 번 파편 수익은 유지, 완료 보너스 없음) → ORDER_BOARD
7. vitest: OrderGenerator 결정성(같은 seed → 같은 카드), 세이브 라운드트립, 깨진 세이브에서도 시작 가능, 상태 머신 전이 표
8. 끝나면 build/test 통과, 콘솔 에러 0, 주문 3회 연속 플레이로 수동 확인 후 커밋
```
**검증**: 게시판 → 건물 → 부수기 → 피날레 → 결과 → 다음 주문이 끊김 없이 반복 / 새로고침해도 돈과 통계 유지 / 10채 연속 후에도 메모리·FPS 유지
